Bytos runs inside Visual Studio Code and uses VS Code's network stack for model
requests and extension updates. The exact proxy settings depend on your VS Code
version and environment.

## Proxy settings

1. Open **Settings** in VS Code.
2. Search for `http.proxy`.
3. Set the proxy URL, for example `http://proxy.example.com:8080`.
4. If your proxy needs authentication, configure it through VS Code's proxy
   settings or your operating system's credential store.
5. Reload VS Code after changing proxy settings.

VS Code also supports `http.proxyStrictSSL` and `http.proxySupport`. Use the
values required by your network; do not disable certificate validation unless
you understand the risk.

## Corporate certificates

If your proxy intercepts TLS, install the corporate root certificate in your
operating system trust store and configure VS Code to trust it. Do not paste
private keys or provider API keys into a proxy configuration file.

## Model provider connectivity

- Cloud providers need outbound HTTPS access.
- Local models through Ollama or LM Studio use a local endpoint such as
  `http://localhost:11434` or `http://localhost:1234`.
- If only the model list is empty, check the provider key/base URL first.

## Diagnostics

VS Code's **Help → Toggle Developer Tools → Console** and the **Output** panel
can show extension/network errors. Do not share API keys or full prompts in a
public issue; redact them first.

For installation problems, see [Installing Bytos](/getting-started/installing-bytos)
and [FAQ](/troubleshooting/faq).
