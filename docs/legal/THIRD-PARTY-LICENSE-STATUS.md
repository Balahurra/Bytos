# Third-party license and attribution status

**Status:** Evidence record for the P2 audit remediation.
**Date:** 2026-11-10
**Scope:** Bytos VS Code extension 1.0.2 and the assets packaged in
`bytos-1.0.2.vsix`.

This document records what is verified, what changed, and what still needs an
owner or legal decision. It is not a legal opinion.

## Method

- The dependency inventory is generated by
  `apps/vscode/scripts/generate-third-party-notices.mjs` from the installed
  dependency tree.
- Distribution is checked against the built extension bundle
  (`apps/vscode/dist/extension.js`), the built webview
  (`apps/vscode/webview-ui/build/`), the VSIX file list, and the VSIX contents.
- The VSIX contains built bundles and runtime assets, not `node_modules`.
  "Not distributed" below means the package marker is absent from the bundles
  and the package itself is not in the VSIX.
- License text is read from each installed package's `package.json`, `LICENSE`,
  or `LICENSE.md`.

### Generator correction

`generate-third-party-notices.mjs` previously walked every directory and called
`collectPackage` on any `package.json` it found. That treated fixture manifests
and private subpath manifests as separate packages. It now collects only real
package roots: a directory directly under `node_modules`, or a scoped package
directly under `node_modules/@scope`. This removed the 7 false entries (#7-#13)
without dropping real dependencies.

## Cline provenance and attribution

### Evidence limitation

The repository history starts with one squashed import
(`822988f "Initial Bytos: rebranded coding agent, ..."`). There is no upstream
remote or merge base. No file can be proven byte-identical to a specific Cline
commit from this history alone. The detailed classification is in
`docs/release-audit/02-CODE-ORIGIN-MAP.md`.

### Attribution status

- `LICENSE` contains the Apache-2.0 text, preserves the Cline copyright, adds the
  Bytos modification notice, and identifies the upstream Cline project.
- `NOTICE` identifies Cline, the upstream URL, Apache-2.0, the upstream
  copyright, and disclaims affiliation.
- README and the website footer disclose the Cline foundation and independence.
- 14 modified code files carry the Cline header; some mechanically modified files
  are covered only at the bundle/notice level.
- No Cline logo is used.

**Status:** the attribution structure is preserved and conservative. Provenance
remains **inferred** for Category A, and the squashed history prevents stronger
claims. Legal review is still required before a large public launch.

## Brand and trademark ownership

- `TRADEMARKS.md` says the Bytos name, logo, app icon, and visual identity are
  "trademarks of the Bytos project."
- The repository contains **no trademark registration evidence**. Do not claim
  that Bytos is a registered trademark.
- The copyright line says "Bytos contributors", which is not a legal entity.
- The Marketplace publisher is `bytos`; the GitHub owner is `Balahurra`; the
  domain is `bytos.dev`. The owner must confirm the legal entity that controls
  these identities.
- Social icons under `apps/vscode/assets/icons/social/` are third-party brand
  logos (Discord, GitHub, LinkedIn, Reddit, X) shipped in the VSIX for links.
  Their source and trademark terms are not documented in the repository.
  Nominative linking is plausible, but owner/legal review is required before
  relying on it.
- Brand assets under `assets/branding/` and the screenshots/video are not proven
  third-party or Bytos-authored from the repository history. Owner confirmation
  is required.

2. Confirm the trademark status of the Bytos name and logo. Do not publish a

4. Confirm authorship/rights for brand assets, screenshots, and demo video.
5. Obtain legal review of the 5 unresolved entries if any of them will ever be
   distributed.
6. Obtain legal review of Cline Category A inference before a large public
   launch.
7. Confirm whether the CC-BY codicons notice meets the intended attribution
   standard for the target markets.
