## Settings

Bytos keeps its product settings inside the extension:

- **Settings → API Configuration** — provider, API key, model, and optional base
  URL.
- **Settings → General** — approval and telemetry preferences.
- **Settings → Voice** (Windows x64) — microphone, language, and speech model.
- **Settings → Auto Phase Plan** — up to 10 sequential phases, per-phase
  provider/model/API key/MCP, failure policy, and reporting.

## API keys

Provider API keys and OAuth tokens are written to **VS Code SecretStorage** (the
OS credential store). They are never written to a plaintext settings file and are
never sent to the webview. The UI only receives a masked value and a
configured/not-configured status.

See `apps/vscode/PRIVACY.md` for the full data map.

## Workspace customization

Bytos reads workspace-scoped customization files:

- `.bytosrules` — project rules;
- `.bytos/skills` — reusable skills;
- hooks and Bytos ignore files as documented in the Customization section.

See [Bytos rules](/customization/bytos-rules), [Skills](/customization/skills),
[Hooks](/customization/hooks), and [Bytos ignore](/customization/bytosignore).

## Task history and checkpoints

Task history and checkpoints are stored by the extension in VS Code storage.
Use **History** to review or delete tasks, and the checkpoint controls to compare
or restore an earlier step.

## Telemetry

Telemetry is **off by default**. It is enabled only by an explicit opt-in in
**Settings → General**. When disabled, Bytos does not send PostHog events or
feature-flag requests.

## Data and privacy

- There is no Bytos backend in this build.
- Model requests go directly from your machine to the provider you choose.
- Local models do not leave your machine.
- See `PRIVACY.md` and `SECURITY.md` for details.
