Bytos configuration lives in two scopes:

- **Global configuration** in `~/.bytos/` (applies globally across all Bytos applications, including IDE, CLI, and SDK)
- **Project configuration** in `.bytos/` (applies only to the current workspace)

## Configuration Directory Layout

Bytos stores shared configuration across a few well-known locations. The primary root is `~/.bytos/`, with structured app state under `~/.bytos/data/`:

```text
~/.bytos/
  data/
    settings/
      providers.json           # API keys and provider configuration
      global-settings.json     # Global settings
      bytos_mcp_settings.json  # MCP settings
    teams/                     # Team state
    sessions/                  # One folder of messages per session
    db/                        # SQLite databases (sessions.db, cron.db, ...)
    logs/                      # CLI and hub logs
  rules/                       # Global rules
  workflows/                   # Global workflows
  hooks/                       # Global hooks
  skills/                      # Global skills
  agents/                      # Global agent definitions
  plugins/                     # Global plugins (.js, .ts)
  cron/                        # Global cron specs
```

Additional global search paths supported by the code:

```text
~/Documents/Bytos/
  Rules/                       # Additional global rules
  Hooks/                       # Additional global hooks
  Plugins/                     # Additional global plugins
  Workflows/                   # Additional global workflows
```

Project-level configuration lives in `.bytos/` at your repository root:

```text
.bytos/
  rules/                       # Project rules
  workflows/                   # Project workflows
  skills/                      # Project skills
  hooks/                       # Lifecycle hooks
  agents/                      # Project agent definitions
  plugins/                     # Project plugins
```

Notes:

- Global provider settings, global settings, and MCP settings are stored under `~/.bytos/data/settings/`.
- Global rules, workflows, hooks, skills, agents, plugins, and cron specs resolve directly under `~/.bytos/`.
- Rules, hooks, plugins, and workflows may also be discovered from `~/Documents/Bytos/` for compatibility.
- In a project, Bytos also reads the older `.bytosrules/` layout (rules, plus its `workflows/`, `skills/` and `hooks/` folders), `AGENTS.md` at the project root, and skills in `.agents/skills/`. Globally, it also reads `~/.agents/AGENTS.md` and skills in `~/.agents/skills/`.

## What Goes Where?

- Use **global (`~/.bytos/`)** for defaults shared across all Bytos applications (IDE, CLI, SDK) on your machine.
- Use **project (`.bytos/`)** for team-shared behavior that should travel with the repo.

Commit `.bytos/` files you want to share with your team. Keep secrets out of the repo.

## Configure Through the CLI

Use the interactive config UI:

```bash
bytos config
```

From there, you can view/edit:

- Settings (global + workspace)
- Rules
- Skills
- Hooks

## Useful Configuration Commands

Use a custom configuration directory:

```bash
bytos --config /path/to/custom/config "your task"
```

Or via environment variable:

```bash
export BYTOS_DIR=/path/to/custom/config
bytos "your task"
```

Open the CLI log file (`~/.bytos/data/logs/bytos.log`, or the file `BYTOS_LOG_PATH` names) when troubleshooting:

```bash
bytos doctor log
```

## Environment Variables

| Variable | Description |
|----------|-------------|
| `BYTOS_DIR` | Custom configuration directory (replaces `~/.bytos/`), like `--config` |
| `BYTOS_DATA_DIR` | Custom data directory (replaces `~/.bytos/data/`) |
| `BYTOS_HUB_PORT` | Port of the local hub (default: `25463`) |
| `BYTOS_HUB_ADDRESS` | Hub address for `bytos schedule` commands, like their `--address` option |
| `BYTOS_SESSION_BACKEND_MODE` | Force backend mode (`local`, `hub`, `remote`, `auto`) |
| `BYTOS_SANDBOX` | Enable sandbox mode |
| `BYTOS_SANDBOX_DATA_DIR` | Sandbox session storage directory |
| `BYTOS_HOOKS_DIR` | Additional hooks directory |
| `BYTOS_LOG_PATH` | CLI log file (default: `~/.bytos/data/logs/bytos.log`). `bytos doctor log` opens it |

### BYTOS_DATA_DIR

```bash
export BYTOS_DATA_DIR=/custom/path/to/bytos
bytos "your task"
```

## Security Notes

<Warning>
Only use rules, hooks, skills, and plugins from sources you trust.
</Warning>

Hooks and plugins can execute code. Review them like any other executable artifact before adding them globally or to a project.
